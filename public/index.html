01. Process & Network Binding

Missing Dev Script & Telnet Port 4000

The original package.json only provided "start": "node ./ranvier -v" with no "dev" or "build" scripts, and ranvier.json targeted raw TCP Telnet on port 4000.

Resolved: Wired npm run dev to launch Ranvier on 0.0.0.0:3000 with a multiplexed HTTP + WebSocket server event listener.

02. Uninitialized Git Submodule Bundles

Empty /bundles Directory

Ranvier's core engine is unopinionated and delegates all game content, networking, attributes, commands, and quests to bundles. Because "bundles": [] was empty, the server exited immediately without opening a socket.

Resolved: Built the self-contained bundles/ranvier-core bundle with areas, NPCs, items, quests, skills, effects, commands, and channels.

03. Player Hydration & Attribute Contracts

Admin.json Schema Compatibility

The seed character data/player/Admin.json references room limbo:white and 8 specific attributes (strength, agility, intellect, stamina, health, armor, energy, critical). Missing any attribute throws a fatal Character.hydrate() error.

Resolved: Registered all 8 attributes with computed formulas in attributes.js and hydrated limbo:white.

Modernization & Refactoring Architecture

How to refactor RanvierMUD’s Authentication, Database Persistence, and Realtime Multiplayer layers while preserving its event-driven bundle architecture.

01. Authentication Refactoring

From Terminal Prompts to OAuth2 / Firebase Auth

Original Design: Sequential input-events/ state machine prompting for username & plaintext password over Telnet, verified via synchronous bcryptjs.compareSync() against local JSON files.

Modern Refactoring: Authenticate users in the web client via Firebase Authentication (Google OAuth, GitHub, Email/Password) and pass the signed ID token during the WebSocket handshake.

// WebSocket Upgrade Token Verification
wss.on('connection', async (ws, req) => {
  const token = extractBearerToken(req);
  const decoded = await admin.auth().verifyIdToken(token);
  const account = await state.AccountManager
    .loadAccount(decoded.uid);
  const player = await state.PlayerManager
    .loadPlayer(state, account, decoded.name);
  player.hydrate(state);
});
02. Database & EntityLoader Refactoring

Custom Firestore / PostgreSQL DataSource

Original Design: ranvier-datasource-file writes synchronous JSON files to data/account/ and data/player/, which risks race conditions and data loss on ephemeral cloud containers.

Modern Refactoring: Implement a custom Ranvier DataSource in ranvier.json backed by Cloud Firestore (for document-native Player.serialize() trees) or Cloud SQL PostgreSQL (JSONB columns).

// FirestoreDataSource for Ranvier EntityLoaderRegistry
class FirestoreDataSource {
  async fetch(config, id) {
    const snap = await db.collection(config.collection)
      .doc(id.toLowerCase()).get();
    return snap.exists ? snap.data() : null;
  }
  async update(config, id, data) {
    await db.collection(config.collection)
      .doc(id.toLowerCase())
      .set(data, { merge: true });
  }
}
03. Realtime Multiplayer Transport

Hybrid WebSocket TransportStream + Delta Sync

Original Design: Raw TCP sockets emitting unstructured ANSI strings; clients had to scrape text with regexes (Mudlet/TinTin++) to build health bars or maps.

Modern Refactoring: Extend Ranvier.TransportStream over WebSockets on port 3000 (implemented live in this app!). Every tick and command emits both narrative ANSI text and structured JSON state deltas.

// Implemented in bundles/ranvier-core/server-events/web-server.js
class WebSocketStream extends TransportStream {
  write(message) {
    this.ws.send(JSON.stringify({
      type: 'terminal', text: message
    }));
  }
  executeGoAhead() {
    this.syncState(); // Pushes room, vitals, map & quests
  }
}
